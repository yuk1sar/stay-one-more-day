# Письма автору в Telegram

На сайте доступны независимые действия: «Сохранить себе» (localStorage) и «Отправить автору» (серверная функция, явное согласие). Уже сохранённые записки не отправляются автоматически. Функция не пересылает IP, имя или Telegram-профиль посетителя. Не называйте передачу полностью анонимной: запрос проходит через Vercel, а письмо — через Telegram.

## Подключение

1. Откройте https://t.me/StayOneMoreDayBot со своего аккаунта и нажмите Start.
2. Из папки проекта запустите `powershell -NoProfile -File scripts/telegram-chat-id.ps1`. Скрипт запросит токен скрытым вводом, проверит имя бота и попросит отправить уникальную команду боту. Затем покажет только ваш TELEGRAM_CHAT_ID. Токен не сохраняется в файлы. Если PowerShell блокирует скрипт, не меняйте системную политику вслепую — обратитесь за помощью.
3. В Vercel откройте проект stay-one-more-day → Settings → Environment Variables. Добавьте для Production:
   - TELEGRAM_BOT_TOKEN — токен из BotFather.
   - TELEGRAM_CHAT_ID — число из скрипта (ваш личный чат с ботом, НЕ имя бота).
4. Выполните `npx vercel --prod` из этой папки. После изменения переменных требуется новый деплой.
5. На опубликованном сайте отправьте несекретный тестовый текст с согласием и проверьте доставку в свой Telegram. Это единственная окончательная проверка подключения.

Не добавляйте к именам секретов префикс VITE_: такие переменные могут попасть в браузер. Не отправляйте токен в чат и не включайте его в Git. .env-файлы исключены из Git и ZIP.

## Поведение и ограничения

Обычный `npm run dev` запускает только Vite; функцию api/letter.js выполняет Vercel. Проверяйте доставку на деплое с настроенными секретами. Без секретов API возвращает «отправка пока не подключена».

Успех показывается только после успешного ответа Telegram sendMessage. Текст не удаляется и не сохраняется автоматически. При таймауте доставка считается неизвестной: автоматического повтора нет. Повтор может создать копию. Клиент блокирует двойное нажатие и повтор того же текста до перезагрузки.

Есть проверка длины (3000 символов), согласия, языка, Origin, скрытое поле против простых ботов и ограничение частоты по IP в памяти экземпляра функции. Это НЕ распределённая защита: при нескольких экземплярах или холодном старте лимит сбрасывается. Для публичной нагрузки настройте Vercel Firewall/rate limiting или подключите постоянное хранилище лимитов. Origin и скрытое поле не защищают от целевого спама.

Содержимое писем и токен не логируются кодом функции. Отправленные письма хранятся в Telegram автора; сайт не даёт ответа и не обеспечивает экстренное наблюдение. Лимит Telegram на сообщения также может временно приводить к ошибке отправки.

Письма принимаются с сайта и непосредственно в Telegram после явного подтверждения. На новые письма из Telegram автор может отвечать текстом через функцию «Ответить» в своём Telegram.

Проверка обработчика без сети: `node --test tests/letter.test.mjs`.

Документация: https://core.telegram.org/bots/api#sendmessage и https://vercel.com/docs/functions/runtimes/node-js

## Команды Telegram

Добавлен api/telegram.js: /start, /write, /help, /site, /about, /language и inline-кнопки на RU/EN/AZ. /write предлагает написать прямо в Telegram одним сообщением до 3000 символов. Бот показывает текст, объяснение и кнопки «Отправить автору», «Отменить», «Написать заново». Только подтверждённое письмо передаётся в TELEGRAM_CHAT_ID. Фото, файлы и голосовые сообщения пока не поддерживаются. На новые письма из Telegram можно ответить текстом через функцию «Ответить».

Подключение после `npx vercel --prod`: `powershell -NoProfile -File scripts/connect-telegram.ps1`. Вставьте токен в скрытый ввод. Скрипт проверит имя бота, доступность нового обработчика, зарегистрирует webhook и проверит его адрес. Секрет webhook вычисляется из токена через HMAC; отдельная переменная не нужна. Токен и секрет не печатаются и не сохраняются. После смены токена в Vercel нужен новый деплой и повторный запуск скрипта. Webhook заменяет предыдущий адрес обработки для этого бота.

После подключения проверьте /start, /help и язык в самом боте. Проверки кода выполняются с подставным API и не подтверждают реальную доставку.

Команды используют язык профиля Telegram (неподдерживаемый — EN). Кнопки сохраняют выбранный язык в callback_data без базы данных. Страна помощи выбирается явно. URL формы содержит только язык, не текст письма. Секрет в заголовке проверяется до обработки. Групповые сообщения и сообщения старше пяти минут игнорируются. Входящий текст не логируется нашим кодом. Защита от повторных update_id действует только в пределах экземпляра функции; после холодного старта возможен повтор ответа меню. Подтверждение письма подписано HMAC и привязано к чату и полному тексту. Перед передачей автору бот удаляет клавиатуру подтверждения в Telegram. Повторное нажатие с неизменившейся пустой клавиатурой отклоняется Telegram; при любой ошибке этого шага пересылка не выполняется. Это не транзакция: сбой после удаления кнопок может оставить письмо неотправленным. При таймауте sendMessage доставка неизвестна, автоматического повтора нет. Отдельное повторное письмо может создать дубликат. Сбой доставки квитанции посетителю не повторяет письмо автору.

При установленном webhook скрипт telegram-chat-id.ps1 с getUpdates больше не работает; ранее сохранённый TELEGRAM_CHAT_ID остаётся действительным.

Черновики хранятся как сообщения в личном чате с ботом, а не в базе на Vercel. Отмена не удаляет эти сообщения из Telegram. Редактирование исходного сообщения не меняет уже показанный черновик: для новой версии выберите «Написать заново», что отменяет старые кнопки. Язык ответа на ForceReply определяется по тексту приглашения; без ответа на приглашение используется язык профиля Telegram. Перед отправкой на RU/EN/AZ объясняется, что автор увидит имя и @username при наличии и сможет ответить через бота. Эти данные берутся из callback_query.from после подтверждения; ручной ввод не нужен.

Для существующего webhook достаточно `npx vercel --prod`; токен и адрес остаются прежними. Проверяйте реальный цикл /write → текст → отмена и /write → текст → отправка после деплоя. Локальные тесты подставляют Telegram API.

## Ответ автора

Новые письма из Telegram содержат имя, @username при наличии и подписанную служебную строку [reply:…]. В личном чате с ботом нажмите «Ответить» на такое письмо и отправьте текст до 3000 символов. Только TELEGRAM_CHAT_ID может отправлять ответы. Получатель и язык проверяются по HMAC-подписи всего исходного письма и владельца; исходное письмо должно быть сообщением нашего бота. Без username ответ работает по chat ID. Посетитель получает текст с подписью «Ответ автора» на своём языке и кнопкой «Написать ещё».

Старые письма без подписи и письма с сайта не поддерживают ответ. Фото, файлы и голосовые сообщения пока не поддерживаются. При блокировке бота или ошибке сети автору сообщается, что доставка не подтверждена. Автоматического повтора отправки при обработанной ошибке нет. Кэш update_id остаётся локальным экземпляру: при аварийном завершении между доставкой ответа и HTTP-подтверждением повтор Telegram может создать копию ответа. Новых секретов не требуется; после деплоя протестируйте письмо и ответ с отдельного Telegram-аккаунта.

## Ответ на письмо с сайта через Telegram

В форме есть выбор: «Хочу получить ответ в Telegram» или «Отправить без ответа». Второй вариант использует прежнюю отправку без обратного адреса. Для первого подключите Upstash Redis и задайте в Vercel (Production) переменные UPSTASH_REDIS_REST_URL и UPSTASH_REDIS_REST_TOKEN из панели базы данных. Используется REST API, пакеты устанавливать не нужно. Не добавляйте VITE_ к секретам. Затем выполните npx vercel --prod; существующий webhook менять не нужно.

Создать базу можно через https://console.upstash.com/ (Redis). Выберите подходящий тариф самостоятельно. Значения REST URL и REST Token находятся в деталях базы; токен должен иметь право записи. Не используйте READ_ONLY_TOKEN. Инструкция провайдера: https://upstash.com/docs/redis/howto/connect-with-upstash-redis

После согласия сайт сохраняет зашифрованный AES-256-GCM черновик с TTL 900 секунд и выдаёт ссылку с 192-битным случайным кодом. В ссылке нет текста, имени или профиля. Код является секретом доступа к черновику — его нельзя передавать другим. Ключ шифрования выводится из серверного токена бота, поэтому смена токена делает оставшиеся ссылки недействительными. Upstash хранит шифротекст, а Vercel обрабатывает открытый текст в памяти; код не логирует письма. После /start w_… Telegram-обработчик атомарно забирает и удаляет черновик через GETDEL. Ссылка одноразовая. Пользователь видит письмо в боте и подтверждает передачу автору, включая раскрытие имени и @username. После этого используются существующие подписанные письма и ответы автора.

Если Telegram недоступен после GETDEL, ссылка всё равно использована: человек получает предложение создать новую на сайте. Сайт не стирает текст; для сохранения после закрытия страницы пользователь должен отдельно нажать «Сохранить себе». Статус на сайте сообщает только о готовности ссылки, а не о доставке автору. Доставка подтверждается в боте. Неоткрытые черновики удаляются по TTL. Перенесённое письмо остаётся сообщением в Telegram.

Лимит создания ссылок хранится в Redis: один запрос в минуту на хеш IP. TTL лимита 60 секунд. Ограничение не заменяет защиту от распределённого спама. Без Redis обычная отправка без ответа и сообщения непосредственно в боте продолжают работать; подготовка ссылки показывает ошибку без ложного успеха.

Проверить после подключения: написать новый тестовый текст на сайте → выбрать ответ в Telegram → согласиться → продолжить → открыть бота и нажать Start → подтвердить письмо → ответить на него из аккаунта автора. Дополнительно проверить повторное открытие использованной ссылки: текст не должен выдаваться повторно.
